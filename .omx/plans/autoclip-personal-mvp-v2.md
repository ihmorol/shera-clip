# AutoClip personal MVP v2: Zoom class to reviewed social clips

Status: historical implementation plan, 2026-09-24. The owner-confirmed [Shera Clip PRD](../../docs/PRD.md) is now authoritative. This file predates the direct Zoom API import and later product decisions; do not implement from it where the PRD differs. No application code or representative class media exists in this workspace yet.

## Requirements summary

The app runs on the operator's laptop and serves its interface only at `http://127.0.0.1`, accessible in the laptop's browser. It has no cloud deployment, public website, remote database, or user accounts. The operator selects a 2–3 hour Zoom MP4 and its VTT transcript. The app produces a shortlist of coherent teaching moments, lets the operator review and adjust each one, and downloads approved video files plus a categorized posting package for a business Facebook Page and YouTube channel. Missing, corrupt, or badly misaligned VTT can be replaced by a paid transcription API after showing a cost estimate. Nothing is posted automatically. Successful operation means publishable clips from real classes, not merely successful API calls or valid MP4 files.

The original analysis identified absolute-time alignment, keyframe cuts, VTT parsing, manifest, resume, and quality calibration as gaps ([v1.0 §§3–5](../../plans/autoclip-jev-engine-analysis.md)). The addendum reduced model scope but left conflicting chunk, frame, API, and state contracts ([v1.1 §§15–19](../../plans/autoclip-jev-engine-stress-test-v1.1.md)). This plan resolves those conflicts.

## Operator workflow and scope

1. **Import:** select a local MP4 and optional Zoom VTT; show upload progress, source duration, audio/video properties, transcript status, and storage estimate. Stream the upload to disk in resumable chunks; verify final byte count and SHA-256 before analysis. A local-path import is an additional convenience, never the only input method. Do not send video to a model.
2. **Transcript:** parse VTT into timed cues, retaining text and speakers. Show a 3-point alignment check near the start, middle, and end. If VTT is absent, unreadable, incomplete, or out of sync, offer offset correction/re-upload or an explicit paid fallback; show estimated cost before sending audio. The initial fallback is OpenAI `whisper-1` with `verbose_json` word/segment timestamps. Extract compressed audio, split it into files below 25 MB at silence/sentence breaks, transcribe each with a language hint when needed, restore absolute offsets, and check joins for gaps and duplicates. A failed fallback leaves a resumable job, not a silent empty result. Mixed Bangla/English terms must be checked on a real sample before this path passes.
3. **Discover:** create candidate moments from speech/sentence boundaries with neighboring context. A candidate must contain a complete, understandable teaching point; do not use rigid 30-second cuts as the final clip definition. Logical analysis windows may overlap across 10-minute marks. Store every candidate on the original video's zero-based timeline. Never create 10-minute video chunks for scoring.
4. **Rank and categorize:** Jev makes bounded, typed judgments on each candidate's transcript: topical category, standalone clarity, educational value, and opening strength. A versioned policy combines those scores into a ranked list. Apply deterministic duration, silence, overlap, and duplicate rules in code. Selection is calibrated against hand labels, not a fixed `0.8` score. Low confidence goes to review, not automatic rejection. If Jev fails, hold the job for retry or a configured alternative decision model; never invent rankings. Visual quality, privacy, rights, and factual accuracy are checked during human review because text-only Jev cannot see or verify them.
5. **Review:** show each candidate with playable preview, source timestamp, transcript, category, scores/reasons, and audio waveform. The operator can reject, change category/title/caption, adjust in/out points, and choose a portrait layout. Display what a Facebook/YouTube viewer will actually see. Only explicitly approved clips enter export.
6. **Export:** render approved clips from the original MP4 with accurate seeking and short re-encoding. Deliver 9:16 MP4 for Facebook Reels and YouTube Shorts, editable subtitle file, thumbnail frame, operator-edited title/description/CTA, category, source/time provenance, and CSV/JSON posting index. Default portrait layout preserves the full Zoom screen inside the canvas; crop or speaker-focused layout requires preview selection so teaching slides cannot be cut off. Captions are optional burn-in and editable before rendering. Manual upload to the user's channels is the MVP boundary. Record the eventual post URL and basic performance metrics for later rubric improvement; never claim revenue from a model score.

Default target is **15–45 seconds**; allow **up to 60 seconds** when the explanation needs it. Never truncate a sentence merely to hit a preferred length. Longer output is a later option, although YouTube currently accepts square/vertical Shorts up to three minutes ([YouTube Help](https://support.google.com/youtube/answer/15424877?hl=en)). Meta says Facebook video sharing is being unified as Reels without a universal length/orientation limit; the 9:16 export is a deliberate mobile presentation choice, not a claimed platform requirement ([Meta announcement](https://about.fb.com/news/2025/06/making-it-easier-create-videos-facebook/), [Meta creative guidance](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)).

Out of scope for MVP: cloud hosting, public network access, remote database, accounts/sync across devices, direct Facebook/YouTube publishing, automatic revenue prediction, face tracking, generative B-roll, full-video re-encoding, and unattended approval. The browser is only a local interface; processing and files remain on the laptop. The previously requested Jev and fallback transcription APIs are optional outbound calls that require internet access and explicit per-job authorization.

## Contracts that implementation must preserve

### Time and media

- Store boundaries as **zero-based seconds on the original media presentation timeline**: `start_sec`, `end_sec`, `source_hash`. Preserve the probed stream start time and time base as metadata for FFmpeg commands. Require `0 <= start_sec < end_sec <= probed_duration_sec`.
- **Do not persist `round(sec * fps)` frame numbers as identity or cut coordinates.** Zoom recordings can have variable frame timing; frame position is resolved from decoded timestamps only when validating an export. The numeric examples in v1.1 violate their own stated frame invariant ([v1.1 §16](../../plans/autoclip-jev-engine-stress-test-v1.1.md)).
- A transcript is aligned when sampled audible words match their displayed cues within **±1 second** at the start, middle, and end, or the operator corrects the offset. Otherwise block ranking and offer fallback. Record the transcript source and any offset.
- The initial fallback uses OpenAI `whisper-1` because its API exposes word/segment timestamps. Its current file limit is 25 MB, so the implementation must check bytes before every request ([OpenAI transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text)). Record model, language hint, request IDs, chunk offsets, and actual charge when available. Before implementation, document provider data handling and verify current price, supported languages, and timestamp quality on the user's mixed-language material. Retry only retryable failures with bounded backoff; an unknown result is recorded as indeterminate rather than silently resent.
- Logical analysis windows overlap by at least the maximum candidate duration at their edges. Candidate identity and deduplication use absolute time plus source hash, independent of window number.
- Cut from the original source using seek plus decode/re-encode of only the selected span. FFmpeg documents that input seeking can land on an earlier seek point, while accurate transcoding decodes and discards the gap; stream copy preserves that gap ([FFmpeg documentation](https://ffmpeg.org/ffmpeg.html)). No promise of lossless frame-exact stream-copy clips.

### Model and classification

- Jev adapter: OpenRouter `POST /api/alpha/decisions`, pinned `typesafe/jev-1.13`, request `model` + `state` + typed `questions`; parse `choice`, `noul`, and `score` with validated IDs and probabilities. It is **not** a `chat/completions` JSON generator and cannot write titles/descriptions ([OpenRouter Jev guide](https://openrouter.ai/blog/tutorials/how-to-use-jev/)). Keep prompt/rubric/model versions in the manifest. If prose drafting is enabled, use a separate generative model and require operator editing.
- Default mutually exclusive primary categories: **Exam tip**, **Worked example**, **Common mistake and correction**, **Vocabulary/phrase**, **Practice exercise**, **Other**. Optional topic tags: IELTS module, task type, skill, level. A clip can have one primary category and multiple tags; the operator can change them.
- Jev asks three `score` questions, each on an explicitly described 0–4 scale: **educational value**, **standalone clarity**, and **opening strength**. Default rank = `0.45 * value/4 + 0.35 * clarity/4 + 0.20 * opening/4`; ties sort by earlier source time. A `choice` question assigns the primary category. A candidate with value or clarity below 2 remains visible but is below the review shortlist by default. Save this policy and rubric version. Scores are structured judgments, not prose rationales; the UI displays the contributing scores and source excerpt.
- Label “worth reviewing” only when the excerpt contains a complete, relevant takeaway with a usable opening; labelers also flag audio, visual, privacy, rights, and factual concerns separately after watching the video. Jev sees transcript text only. The operator checks the nontext flags, captions, and source claim before approval. A candidate with unresolved privacy/rights concern or misleading caption cannot enter the approved set.
- Choose thresholds from labelled class data. Jev's published pricing is currently $0.042 per million input tokens with free output and a 32K listed context ([OpenRouter model page](https://openrouter.ai/typesafe/jev-1.13/api)); recheck before implementation. Do not budget prompt caching or assert 5–9 second inference latency without measured usage. At 65K billed input tokens the **illustrative** Jev charge is $0.00273, excluding transcription, retries, and other models.

### Artifacts, recovery, and cost

- `source.json`: immutable source hash, media probe, transcript source/offset, schema version.
- `candidates.json`: immutable candidate boundaries, cue IDs, model results, category/tags, rubric/model version. Regenerate on changed source/transcript/rubric; never mutate it for review edits.
- `job.json`: mutable stage and per-chunk/per-clip statuses, errors, retry count, cumulative provider usage and cost; write atomically. Before each paid call, journal `reserved` with a conservative maximum charge, then `in_flight`, then `completed` with response/request ID and actual charge. A crash or timeout after send becomes `indeterminate`; do not automatically resend unless the provider supports idempotency/result lookup. Show the operator the possible duplicate charge before a manual retry. Resume skips durably completed artifacts and rechecks source/config hashes.
- `manifest.json`: final approved clip boundaries, human edits, export paths, checksums, media properties, metadata, provenance, cost, and QA status. Only completed exports appear as ready. A ZIP with video, subtitle, thumbnail, metadata, and index is the user-facing download.
- Set a configurable **maximum external spend per job**, estimate transcription before starting, and reserve worst-case cost before each new paid call; refuse the call when the reservation would exceed the cap. Reconcile reservations against reported usage/cost. Indeterminate calls keep their reservation until resolved. If the cap is reached, stop new paid calls and preserve partial results. Cost and elapsed time are reported by stage; no fixed all-in price or runtime is promised.
- The local server binds only to `127.0.0.1` and rejects non-loopback requests. Uploads, job state, and rendered files stay on the laptop; there is no cloud storage or telemetry. API keys stay in the local server's environment or OS credential store and are never exposed to the browser. Media sent externally is limited to audio for explicitly approved fallback transcription and transcript excerpts for explicitly approved scoring. Show this before the first external call. Without API access, local import, VTT parsing, manual clip selection, review, and export still work; automatic ranking and fallback transcription report that their provider is unavailable. Job deletion is an explicit operator action.

## Acceptance criteria for a usable MVP

| ID | Observable gate |
|---|---|
| A1 | The app starts on the laptop at `127.0.0.1` and is unreachable from another device on the LAN. A representative 2–3 hour Zoom MP4 plus valid VTT imports through the local browser, survives browser refresh/process restart, and resumes without duplicating upload or durably completed API work. Wrong VTT, truncated upload, and unsupported media produce actionable errors. |
| A2 | Missing/misaligned VTT offers a visible paid fallback estimate. One real 2–3 hour class completes fallback under the provider's per-file limit; at three sampled points transcript/media offset is at most 1 second after correction. The operator can stop before any paid call. |
| A3 | Freeze **three representative classes** before tuning: two calibration classes and one untouched held-out class, with at least **60 labelled candidate moments total** and at least 20 in the held-out class. Apply the versioned ranking policy without tuning on the held-out set. At least **7 of its top 10** candidates meet the written “worth reviewing” definition and at least **3** yield approved clips after video review. Report these separately from model confidence; if the gate fails, revise on calibration data and evaluate on a new held-out class before calling the selector production-ready. |
| A4 | Each approved clip has one primary category, optional tags, editable posting text, original-source timestamp, and an export that plays start-to-end with intelligible audio. No approved clip contains cut-off opening/closing words, missing slide content, unreviewed private student details, or knowingly inaccurate captions. |
| A5 | Exported portrait files pass `ffprobe`: video H.264, audio AAC, 9:16, within chosen duration, decodable first/last second, and audio/video stream start/end timestamps differing by at most 200 ms. Inspect at least three early/middle/late exports against the source; when a speaking face is visible, speech and mouth motion have no perceptible new offset. `ffprobe` timing alone does not prove lip sync. Captions and title are legible on a phone-sized preview. |
| A6 | Review approve/reject, boundary edits, rendering failure, budget stop, and restart preserve the operator's choices. Re-run with unchanged hashes does not repeat **durably completed** paid calls; uncertain in-flight calls pause for reconciliation/operator choice. Changed inputs invalidate only dependent stages. |
| A7 | One completed approved package is manually uploaded as **unlisted/private YouTube Short** and a nonpublic Facebook Page draft/test post where the account permits it; confirm video, audio, portrait framing, captions, and title on both platform previews before the workflow is called publish-ready. No public post is required for acceptance. |

The numerical ranking gate is a **proposed product threshold**, not an observed capability or revenue guarantee. If real classes cannot supply three usable clips, the report must say so rather than lower the threshold silently.

## Risks and decisions

| Risk | Mitigation / decision |
|---|---|
| Zoom VTT drifts or repeats rolling captions | Three-point alignment, cue normalization, manual offset, then paid fallback. |
| Fixed clip length removes context | Sentence-based candidates and editable 15–60 second boundaries; reject incomplete teaching points. |
| Zoom slides become unreadable in vertical video | Preserve full frame by default; show phone preview; operator can choose layout. |
| Jev ranks fluent but low-value moments | Domain-labelled calibration, held-out top-10 gate, visible evidence, human approval; alternative model only after measured failure. |
| API price/format/limits change | Pin model, verify current contract before build, log actual usage, enforce spend cap. |
| Source contains student identity, copyrighted music, or wrong claims | Review gate and provenance; no automatic publishing. |
| 3-hour files exhaust disk or fail mid-run | Streamed resumable local upload, disk preflight, atomic stage artifacts, explicit cleanup. |

Decisions: localhost browser workflow for one operator with loopback-only binding and local files/state; optional outbound Jev and ASR calls, with a manual path when unavailable; original-media absolute seconds; logical overlapping transcript windows; sentence-based candidate moments; human approval; 9:16 previewed exports; manual channel publishing. Revisit these only with pilot evidence. Revenue impact must be measured later from actual posts and analytics, not inferred from model scores.
